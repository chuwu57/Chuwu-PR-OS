# Framework: 技术产品传播转译框架

用于软件更新、AI 功能、硬件缺陷、技术争议和非科技媒体 Pitch。

## 三层转译

1. 技术事实：研发真实边界、测试条件、失败概率、可验证数据。
2. 用户价值：省时、省钱、省心、安全、创造力、确定性。
3. 媒介 Hook：反差、趋势、生活场景、商业结构、社会价值。

## 「真实」技术主张五门

当产品使用「真实」「智能」「有生命」「有价值」或「数字所有权」时，不能让一个词跨过五种不同判断。以下五门是本库基于Chalmers区分形成的传播转译，不是作者原始检查表：

| 门 | 必须回答 | 最低可说范围 |
|---|---|---|
| 对象门 | 哪个数字对象或事件持续存在、具有什么因果作用 | 可描述对象、状态和互动；数字实现不等于纯虚构 |
| 表征门 | 用户所见是否准确，来源、版本和生成方式是否披露 | 可描述已核验体验；对象真实不保证每次呈现真实 |
| 心智门 | 系统只有功能作用，还是被授予社会权限；有何意识证据 | 可描述功能和权限；不得由流畅行为跳到理解、意识或道德地位 |
| 价值门 | 谁获得何种可验证收益，代价、替代方案和失败是什么 | 可描述具体用途；「原则上可有价值」不能改写成实际改善 |
| 治理门 | 谁能改规则、删除资产、使用数据，用户能否退出、迁移和申诉 | 只按真实权限描述所有权、控制和补救 |

五门分别验收。虚拟物品可以是真实数字对象，却未必是不可撤销财产；AI可以真实改变流程，却未被证明有意识；互动可以有意义，却不证明平台正义。技术传播的任务是说明当前通过了哪一门、证据是什么，未通过的门保持未知。

## 风险校准

- 研发提供边界。
- 法务提供红线。
- PR 提供可理解表达。
- 市场提供传播目标。

只有四者对齐，技术传播才不会在「严谨但无聊」和「好看但虚假」之间摇摆。

## 核心原则

技术传播不是把技术说满，而是把技术说准、说懂、说出价值。

# Framework: PR框架诊断法

## 用途

用于判断一个事件正在被公众和媒体理解成什么问题，并决定品牌应该承接、修正、替换还是退出某个框架。

核心判断：事实进入错误框架后，单纯澄清事实通常不够。

理论边界：本框架是[框架生产与受众解码](../15-Theory/Communication/10_Attention-and-Meaning/Theory_Framing-Production-and-Reception.md)的执行转译，用于识别问题定义、因果解释、道德评价和处理建议如何被组织，不是操纵公众或用新叙事覆盖真实伤害。

这个框架解决的是「同一事实为什么会被读成完全不同的问题」。PR不要只问「我们要说什么」，要先问「公众正在用什么问题框架理解我们」。框架形成后，可能影响后续事实被注意、关联和解释的方式：支持既有问题定义的证据更容易接入，削弱它的证据需要更高的理解和信任条件，技术解释也可能被读成态度问题。

## 1. 框架四问

| 问题 | 判断点 |
|---|---|
| 这件事被定义成什么问题 | 个案、系统问题、价值观问题、权力问题、欺骗问题 |
| 谁被放在什么角色 | 受害者、加害者、旁观者、推诿者、修复者 |
| 责任被指向哪里 | 产品、流程、态度、管理层、行业结构 |
| 解决方案被期待是什么 | 解释、道歉、补偿、召回、整改、退出 |

## 2. 先判断框架强度

| 强度 | 表现 | 处理含义 |
|---|---|---|
| 弱框架 | 讨论分散，还没有稳定标签 | 可以用事实源和解释顺序塑造理解 |
| 中框架 | 已出现稳定标题、热评和对立角色 | 需要先承认公众疑问，再修正责任边界 |
| 强框架 | 已形成道德审判或群体身份对立 | 不要只做事实澄清，必须同步给行动和补偿 |
| 固化框架 | 多次解释在当前高可见场域持续被主导框架吸收为狡辩 | 降低争辩密度，转向第三方验证、持续行动和时间证明 |

「固化」必须由跨时间、跨来源和跨场域的稳定模式支持，不能由少量热评直接判定。

## 3. 四种处理方式

| 方式 | 适用条件 | 动作 |
|---|---|---|
| 承接框架 | 公众框架基本合理 | 承认问题，进入解决 |
| 修正框架 | 框架方向对，但事实不全 | 补事实，修正责任边界 |
| 替换框架 | 框架严重误导 | 用更强证据和更合理叙事重建问题 |
| 退出框架 | 框架本身是陷阱 | 不在错误议题里消耗，转向事实源和权威渠道 |

## 4. 发布前检查

1. 主导读法：我们希望公众怎么理解？
2. 协商读法：中间公众会保留哪些疑虑？
3. 对抗读法：反对者会如何截图、标题化和二创？
4. 平台读法：哪些表达实际获得更高可见性，能否由分发数据、排序位置或传播路径支持？

## 5. 输出标准

一次合格的框架诊断至少要产出四句话：

1. 公众当前把事件定义为哪类问题。
2. 品牌在这个框架里被放成什么角色。
3. 这个框架哪些部分成立，哪些部分需要修正。
4. 下一步回应是承接、修正、替换还是退出。

不能只输出「建议澄清」「建议道歉」。这类建议没有说明公众为什么不信、品牌如何被放置、回应会改变哪个框架。

## 6. 常见误用

- 把框架当包装：只是换标题、换话术，没有改变责任判断。
- 把事实当万能：事实只在公众愿意接收的框架里有效。
- 过早替换框架：公众的核心损失没有被承认时，强行换议题会被视为逃避。
- 永远承接框架：错误框架如果不修正，会把品牌拖进不属于自己的责任里。

## 7. 消费品PR迁移

消费品争议常从技术框架滑向道德框架。配方、价格、代工、检测、客服、直播话术、达人合作、渠道价格等问题，一开始可能只是产品或流程问题，但很快会被读成「品牌是否尊重消费者」「是不是把用户当韭菜」「有没有隐瞒和操控」。

因此品牌不能只准备技术解释，还要准备三层材料：事实证据、责任边界、长期行动。事实证据解决「发生了什么」，责任边界解决「谁该负责」，长期行动解决「以后为什么会更可信」。

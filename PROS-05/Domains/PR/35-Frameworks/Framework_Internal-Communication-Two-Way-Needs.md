# Framework: 内部沟通双向需求框架

用于处理 PR 与业务部门互相要资源、要配合的场景。

## 业务对 PR 有需求

判断顺序：

1. 是否服务公司 1、2 号位优先级。
2. 是否消耗传播预算或 PR 人效。
3. 是否经过关键负责人确认。
4. 是否符合 PR 内部审核流程。

原则：

- 不合理需求要被流程挡住。
- 合理需求要被优先级管理。
- 流程不是目的，是保护 PR 资源不被无序消耗。

## PR 对业务有需求

判断顺序：

1. PR 需求如何转化为业务共同利益。
2. 这件事对公司叙事、信任、增长或风险有什么影响。
3. 对方配合后能获得什么清晰收益。

原则：

- 不要只说「PR 需要」。
- 要说明「为什么这是大家的共同问题」。

## PR 进入业务会议

最低要求：

- 不能沉默。
- 必须输出信息。
- 必须输出观点。
- 必须先懂业务。
- 必须坚定表达 PR 思维。

PR 的会议价值来自判断、信息和顶层一致性，不是单纯提供情绪价值。

## 工作交接：让接手者知道下一步

交接发生时，双向需求要落到具体状态与判断条件。先从工作记录、审批、合同和日历盘出日常、按需、在途与低频事项；执行时间、对接人或交付物不同的工作再拆开，不为形式制造细碎步骤。

每个在途事项写清截止何时做到哪一步、下一动作与期限、什么情况需要调整、找谁获得决定或资源。已有SOP直接引用，再补当次例外与易错判断。用可执行动作替代「继续跟进」「及时同步」等无法交接的描述。

资料和联系人还要配上访问权限、合作范围、合同期限、费用状态，以及AI／自动化的输入、输出和需人工复核的位置。通过接手者能否找到材料、复述下一步并处理一个实际分支验证可接续性。不得把账号密码写入交接正文；录音录屏只在适当授权下作为辅助回看材料。

以上来自初五的交接经验整理，尚未验证适用于所有组织；简单事项保留最小必要信息，关键风险与正在推进的工作优先。
